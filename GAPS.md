# GAPS.md — Capability Gap Analysis (living doc)

Tracks gaps between the current positioning/one-pager claims and actual
evidence, so progress can be checked against a fixed snapshot rather than
re-assessed from memory each time. First built 2026-07-29, cross-checked
against `uploads/private/capability-summary_v1_draft.md`, `FACTS.md`, and
the 7 real job postings + 2 composite archetypes reviewed
2026-07-14 (see `archive/2026-07-14-adhoc-positioning-statement.md`).

## How to use this doc
- Each gap has an **Opened** date, a **Status**, and a **Log** of dated
  updates (narrowed, closed, or re-confirmed still open).
- Re-run the full analysis roughly monthly, or whenever the one-pager/CV/
  LinkedIn positioning changes materially — add a new dated Log line to
  each gap rather than rewriting the original entry, so the history of
  "what changed since when" stays visible.
- Priority reflects effort-to-close vs. impact on the two core pillars
  (Growth, Transformation) used in every outreach message — re-rank if
  that changes.

### Gap 1 — Growth pillar rests on a single proof point (Priority: High)
- **Opened:** 2026-07-29
- **Status:** Effectively closed (2026-08-03) — pending the already-
  scheduled Gap 1 draft task (week of 08-10) to write it up properly
- **Issue:** DAZN (0-to-1 launch, 1M+ subs/12mo) is the only Growth case
  study in the one-pager. Any client whose growth challenge isn't
  market-entry specifically (acquisition-funnel optimization, pricing/
  monetization, post-launch scaling) has nothing else to point to.
- **Promising lead:** Rakuten's numbers (+20% retention, +30% conversion)
  are genuine growth metrics, currently filed only under Transformation —
  may not need new experience, just re-examination/re-framing of what's
  already in FACTS.md.
- **Log:**
  - 2026-07-29: opened, backlog tasks created (research → draft → review)
  - 2026-08-03: research done (this week's Sprint 4 task). Confirmed via
    conversation: the tech-stack modernization was the *enabler*, but the
    actual growth driver was product innovation he led — (1) mobile-native
    manga reading UX (screen-by-screen swipe vs. full-page view), (2)
    serialized/daily-chapter reading (free daily section drives return
    visits; readers hooked on the story convert to full purchase — drives
    both retention and conversion), (3) per-chapter purchasing (lowers the
    price barrier for price-sensitive readers, e.g. students). This is a
    genuinely distinct Growth story from DAZN — DAZN is 0-to-1 market
    entry, this is **post-launch monetization/engagement innovation**
    (pricing model + engagement mechanic) — exactly the growth-challenge
    type this gap flagged as missing. Gap effectively closeable now;
    next step is the already-scheduled Gap 1 draft task (week of 08-10)
    to write this up as a proper case study for the one-pager/outreach
    material.

### Gap 2 — "AI-driven internal efficiency" claimed but not evidenced (Priority: Medium)
- **Opened:** 2026-07-29
- **Status:** Effectively closed (2026-08-03) — pending the already-
  scheduled Gap 2 draft task (week of 08-10) to write it up properly
- **Issue:** The Indeed proof point (25% ML improvement) is AI applied to
  the *product* (job-matching algorithm), not AI making the *product team
  itself* faster — which is what the Transformation pillar's own wording
  promises. Personal daily AI-tool use is real but not yet a professional
  in-role deliverable.
- **Promising lead:** this repo/workflow itself (Claude Code driving
  outreach drafting, research, standups) is a live, honest example of
  AI-driven product-work efficiency — may be usable as a current, ongoing
  case study rather than requiring a past-job example.
- **Log:**
  - 2026-07-29: opened, backlog tasks created (research → draft → review)
  - 2026-08-03: research done (deliberate exception to the 3-task/day cap,
    done same day as Gap 1). Confirmed via conversation: no in-role,
    professional example exists at any past employer (Indeed, Amazon,
    Rakuten, DAZN) — he has used internal AI tools at these companies but
    was never the one introducing/driving adoption for colleagues or
    day-to-day team usage. This repo genuinely is the first and only real
    example of him personally driving AI-driven efficiency. Unlike Gap 1

    deliverable to find — the promising lead *is* the answer, not a lead
    to chase further.
    **Caveat for the draft step (superseded below):** at the time of this
    entry, the repo appeared to be the only evidence, so the note here was

  - 2026-08-03 (same session, follow-up): a stronger example surfaced —

    gathering data from multiple sources for reporting — tools primarily

    adoption story driven by him, not personal solo tool use — a much
    stronger closer than the repo alone. Gap effectively **closed**: two
    honest examples now exist (StageLync as the primary case study — real
    external team, real adoption outcome; this repo as a secondary,
    ongoing/current example). Not on his CV since it's unpaid mentoring
    rather than a paid engagement — the draft step should decide how to
    reference an unpaid advisory relationship credibly (e.g. framed as
    advisory/mentoring work, consistent with how his other mentoring

  The B2B/SaaS/enterprise-transferability question this week's task
